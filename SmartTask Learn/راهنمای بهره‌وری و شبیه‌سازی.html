1. معرفی سیستم بهره‌وری

چرا تحلیل بهره‌وری؟

در تیم‌های نرم‌افزاری، سنجش کمی عملکرد چالش اساسی است. سیستم بهره‌وری SmartTask این نیاز را با ارائه امتیاز جامع 0-100 و رتبه‌بندی Tier پاسخ می‌دهد:

  • خودآگاهی: کاربر می‌تواند عملکرد خود را با معیارهای واضح ببیند
  • مقایسه: رتبه فرد نسبت به میانگین تیم و Workspace
  • انگیزه: سطوح مختلف (Bronze تا Diamond) هدف‌گذاری ایجاد می‌کنند
  • شفافیت: مدیر پروژه می‌تواند نقاط ضعف را شناسایی کند

2.2 شاخص‌های چهارگانه

هر شاخص با نوار پیشرفت و درصد نمایش داده می‌شود:

شاخص وزن توضیح
Task Completion Rate 40% نسبت تکمیل شده به تخصیص داده‌شده
On-Time Delivery 35% درصد Taskهایی که قبل از Deadline تکمیل شدند
Consistency 15% یکنواختی فعالیت (بدون Gap طولانی)
Quality Score 10% کیفیت کار (تعداد بازگشت/اصلاح کم)

کاربر A:
- Completion Rate: 85%
- On-Time Rate: 90%
- Consistency: 70%
- Quality: 95%

Score = (85 × 0.40) + (90 × 0.35) + (70 × 0.15) + (95 × 0.10)
      = 34 + 31.5 + 10.5 + 9.5
      = 85.5 → Tier: Platinum 💎

3. فرمول محاسبه امتیاز بهره‌وری

3.1 Task Completion Rate (40%)


int totalAssigned = user.TasksAssigned.Count;
int totalCompleted = user.TasksCompleted.Count;

double completionRate = totalAssigned > 0 
    ? (totalCompleted / (double)totalAssigned) * 100 
    : 0;

مثال:

  • 50 Task تخصیص داده شده
  • 42 Task تکمیل شده
  • Completion Rate = 84%

3.2 On-Time Delivery Rate (35%)


int completedTasks = user.TasksCompleted.Count;
int onTimeTasks = user.TasksCompleted
    .Count(t => t.CompletedDate <= t.DueDate);

double onTimeRate = completedTasks > 0 
    ? (onTimeTasks / (double)completedTasks) * 100 
    : 0;

مثال:

  • 42 Task تکمیل شده
  • 38 Task به‌موقع تکمیل شده
  • On-Time Rate = 90.5%

3.3 Consistency Rate (15%)

Consistency یکنواختی فعالیت را اندازه می‌گیرد. اگر کاربر هر روز کار کند، Consistency بالاست؛ اگر یک هفته کار کند و یک هفته غیبت داشته باشد، Consistency پایین است.


// محاسبه فاصله روزهای فعالیت
var activityDates = user.TasksCompleted
    .Select(t => t.CompletedDate.Date)
    .Distinct()
    .OrderBy(d => d)
    .ToList();

var gaps = new List<int>();
for (int i = 1; i < activityDates.Count; i++)
{
    gaps.Add((activityDates[i] - activityDates[i-1]).Days);
}

// هر Gap بیش از 3 روز، Consistency را کاهش می‌دهد
int penaltyDays = gaps.Where(g => g > 3).Sum(g => g - 3);
double consistencyRate = Math.Max(0, 100 - (penaltyDays * 2));

مثال:

  • فعالیت: روز 1، 2، 3، 7، 8، 9
  • Gap: 4 روز (بین روز 3 و 7)
  • Penalty: (4 - 3) × 2 = 2 نمره کسر
  • Consistency = 98%

3.4 Quality Score (10%)

Quality بر اساس تعداد اصلاحات و بازگشت Task محاسبه می‌شود.


int totalCompleted = user.TasksCompleted.Count;
int tasksWithRevisions = user.TasksCompleted
    .Count(t => t.Revisions > 0 || t.ReturnedCount > 0);

double qualityScore = totalCompleted > 0 
    ? ((totalCompleted - tasksWithRevisions) / (double)totalCompleted) * 100 
    : 100;

مثال:

  • 42 Task تکمیل شده
  • 4 Task نیاز به اصلاح داشته
  • Quality = (38 / 42) × 100 = 90.5%

3.5 فرمول نهایی


double productivityScore = 
    (completionRate   * 0.40) +
    (onTimeRate       * 0.35) +
    (consistencyRate  * 0.15) +
    (qualityScore     * 0.10);

مثال کامل:

شاخص مقدار وزن حاصل‌ضرب
Completion 84% 40% 33.6
On-Time 90.5% 35% 31.675
Consistency 98% 15% 14.7
Quality 90.5% 10% 9.05
مجموع - - 89.025

→ امتیاز نهایی: 89 → Tier: Platinum 💎

4. سطوح بهره‌وری (Tiers)

جدول Tiers

Tier آیکن بازه امتیاز رنگ توضیح
Bronze 🥉 0 - 40 #CD7F32 مبتدی - نیاز به بهبود
Silver 🥈 41 - 60 #C0C0C0 متوسط - عملکرد قابل قبول
Gold 🥇 61 - 80 #FFD700 خوب - بالاتر از میانگین
Platinum 💎 81 - 94 #E5E4E2 بسیار خوب - عملکرد عالی
Diamond 👑 95 - 100 #B9F2FF نخبه - بهترین عملکرد

محاسبه Tier


ProductivityTier GetTier(double score)
{
    return score switch
    {
        < 41 => ProductivityTier.Bronze,
        < 61 => ProductivityTier.Silver,
        < 81 => ProductivityTier.Gold,
        < 95 => ProductivityTier.Platinum,
        _    => ProductivityTier.Diamond
    };
}

انگیزه Tier

  • Bronze → Silver: باید Completion Rate را بالا ببرید
  • Silver → Gold: تمرکز روی On-Time Delivery
  • Gold → Platinum: Consistency و Quality حیاتی است
  • Platinum → Diamond: باید در همه شاخص‌ها +95% باشید

7. سیستم شبیه‌سازی پروژه

چرا شبیه‌سازی؟

در پروژه‌های پیچیده، تأخیر یک Task می‌تواند کل پروژه را به تأخیر بیندازد. سیستم شبیه‌سازی این پرسش‌ها را پاسخ می‌دهد:

  • کدام Taskها بحرانی هستند؟ (تأخیر آن‌ها پروژه را عقب می‌اندازد)
  • اگر Task X به اندازه Y روز تأخیر کند، چه اتفاقی می‌افتد؟
  • کدام Taskها Slack (انعطاف) دارند؟ (می‌توان آن‌ها را دیرتر شروع کرد)

مفاهیم کلیدی

Critical Path (مسیر بحرانی)

مسیر بحرانی زنجیره‌ای از Taskهایی است که هیچ Slack ندارند. تأخیر در هر کدام، مستقیماً پروژه را به تأخیر می‌اندازد.


Task A ──→ Task B ──→ Task C ──→ Task D
  (5d)      (3d)      (2d)      (4d)
         ↑ Critical Path (14 days) ↑
           
Task E ──→ Task F
  (2d)      (1d)
   ↑ Non-critical (Slack: 11 days) ↑
  • Task A, B, C, D: بحرانی (Slack = 0)
  • Task E, F: غیربحرانی (می‌توان 11 روز دیرتر شروع کرد)

Slack Time (زمان انعطاف)

Slack = فاصله‌ای که می‌توان یک Task را بدون تأثیر روی پروژه به تأخیر انداخت.


Task X:
- Earliest Start: روز 5
- Latest Start: روز 9
- Slack = 9 - 5 = 4 روز

الگوریتم


public CriticalPathDto AnalyzeCriticalPath(int projectId)
{
    var tasks = GetProjectTasks(projectId);
    
    // Forward Pass: محاسبه Earliest Start/Finish
    foreach (var task in TopologicalSort(tasks))
    {
        task.EarliestStart = task.Dependencies
            .Select(d => d.EarliestFinish)
            .DefaultIfEmpty(projectStart)
            .Max();
        task.EarliestFinish = task.EarliestStart.AddDays(task.Estimate);
    }
    
    // Backward Pass: محاسبه Latest Start/Finish
    foreach (var task in TopologicalSort(tasks).Reverse())
    {
        task.LatestFinish = task.Dependents
            .Select(d => d.LatestStart)
            .DefaultIfEmpty(projectEnd)
            .Min();
        task.LatestStart = task.LatestFinish.AddDays(-task.Estimate);
    }
    
    // محاسبه Slack
    foreach (var task in tasks)
    {
        task.Slack = (task.LatestStart - task.EarliestStart).Days;
        task.IsCritical = task.Slack == 0;
    }
    
    return new CriticalPathDto { ... };
}

12. نکات کاربردی

برای کاربران

بهبود امتیاز بهره‌وری

Bronze → Silver (40 → 61):

  1. روی Task Completion تمرکز کنید
  2. Taskهای قدیمی را تکمیل کنید
  3. حداقل 1 Task در روز برای Streak

Silver → Gold (61 → 81):

  1. On-Time Delivery را بهبود دهید
  2. Estimateها را واقع‌بینانه تنظیم کنید
  3. Deadlineها را جدی بگیرید

Gold → Platinum (81 → 95):

  1. Consistency حیاتی است
  2. هر روز کار کنید، Gap نداشته باشید
  3. Quality را بالا ببرید (اولین بار درست انجام دهید)

Platinum → Diamond (95 → 100):

  1. باید در همه شاخص‌ها +95% باشید
  2. Zero Gap در Consistency
  3. Zero Revision در Quality

استفاده از شبیه‌سازی

قبل از شروع پروژه:

  1. مسیر بحرانی را شناسایی کنید
  2. منابع را روی Taskهای بحرانی متمرکز کنید
  3. برای Taskهای غیربحرانی Buffer در نظر بگیرید

در طول پروژه:

  1. وقتی یک Task دچار مشکل شد، What-If بزنید
  2. تأثیر را قبل از گزارش به مدیر ببینید
  3. راه‌حل جایگزین پیدا کنید (Fast-track کردن Task دیگر)

برای مدیران پروژه

استفاده از Productivity Metrics

  1. شناسایی عملکرد ضعیف:
  • کاربران Bronze/Silver نیاز به کمک دارند
  • Completion Rate پایین → overload یا مشکل فنی
  • On-Time Rate پایین → Estimateها نادرست است
  1. تشخیص Burnout:
  • Streak ناگهان صفر شد → ممکن است Burnout باشد
  • Consistency پایین → عدم تمرکز یا مشکل شخصی
  1. ارزیابی عادلانه:
  • از امتیاز عددی استفاده کنید، نه احساس
  • Benchmark با میانگین Workspace

استفاده از Simulation

  1. برنامه‌ریزی:
  • قبل از Commit کردن Deadline، Critical Path بزنید
  • Slack Taskها را برای جذب تأخیرات استفاده کنید
  1. مدیریت ریسک:
  • Taskهای High-Risk را What-If کنید
  • برنامه Contingency آماده کنید
  1. گزارش‌دهی:
  • سناریوها را ذخیره و با ذی‌نفعان به اشتراک بگذارید
  • تأثیر تأخیرات را عددی نشان دهید

خلاصه

سیستم بهره‌وری

  • امتیاز 0-100 از 4 شاخص: Completion (40%), On-Time (35%), Consistency (15%), Quality (10%)
  • 5 Tier: Bronze → Silver → Gold → Platinum → Diamond
  • Streak: روزهای متوالی فعالیت برای حفظ انگیزه
  • Benchmark: مقایسه با میانگین Workspace

سیستم شبیه‌سازی

  • Critical Path: Taskهایی که تأخیر آن‌ها پروژه را عقب می‌اندازد
  • Slack Time: انعطاف Taskهای غیربحرانی
  • What-If: شبیه‌سازی تأخیر و دیدن تأثیر قبل از اتفاق
  • Scenario Management: ذخیره و مقایسه سناریوهای مختلف
