۱. سطوح دسترسی Public/Private فضاهای کاری

۱.۱ مفهوم

در هنگام ایجاد یک Workspace (فضای کاری)، کاربر می‌تواند یکی از دو حالت زیر را انتخاب کند:

حالتنمادتوضیح
خصوصی (Private)🔒فقط اعضای دعوت‌شده می‌توانند ببینند
عمومی (Public)🌍همه کاربران سامانه می‌توانند ببینند و بپیوندند

۱.۲ پیاده‌سازی در کد

تعریف Enum:

// Models/Enums/VisibilityType.cs
public enum VisibilityType
{
    Private = 1,
    Public = 2
}

ذخیره در مدل Workspace:

// Models/Entities/Workspace.cs
public VisibilityType Visibility { get; set; } = VisibilityType.Private;

مقدار پیش‌فرض Private است.

۱.۳ منطق کنترل دسترسی

متد مرکزی بررسی عضویت در BaseController.cs:

protected async Task<bool> IsWorkspaceMemberAsync(
    ApplicationDbContext context, int workspaceId)
{
    return await context.ProjectMembers
        .AnyAsync(x => x.WorkspaceId == workspaceId
            && x.ApplicationUserId == CurrentUser.UserId
            && x.ViewState);
}

۱.۴ نکته مهم برای دفاع

در نسخه فعلی، مقدار Visibility در دیتابیس ذخیره و در UI نمایش داده می‌شود. کنترل دسترسی واقعی بر اساس عضویت کاربر در Workspace است. برای نسخه‌های آینده، می‌توان قابلیت "مشاهده Workspace‌های عمومی توسط غیراعضا" و "پیوستن بدون دعوت" را اضافه کرد.

۲. ارتباط Backlog → Sprint → User Story → Task

۲.۱ ساختار سلسله‌مراتبی

SmartTask از مدل Scrum برای مدیریت تسک‌ها استفاده می‌کند:

📁 Workspace (فضای کاری)
 └── 📂 Project (پروژه)
      ├── 📋 Backlog (فقط یکی به ازای هر پروژه)
      │    └── 📝 UserStory (آیتم‌های بک‌لاگ)
      │         └── ✅ Task (وظایف اجرایی)
      │              └── ☑️ SubTask (زیرتسک‌ها)
      │
      ├── 🏃 Sprint (اسپرینت‌ها)
      │    └── 📝 UserStory (آیتم‌های منتقل‌شده از بک‌لاگ)
      │
      └── 🚗 OffroadTask (کارهای خارج از دامنه)

۲.۲ توضیح هر لایه

Backlog (فقط یکی)

هر پروژه دقیقاً یک Backlog دارد. نام پیش‌فرض: Product Backlog. نقش: محل ذخیره User Story هایی که هنوز به اسپرینتی تخصیص نداده‌اید.

User Story

زیرمجموعه Backlog (فیلد BacklogId). می‌تواند به Sprint تخصیص داده شود (فیلد SprintId که nullable است).

  • اگر SprintId = null → هنوز در بک‌لاگ منتظر است
  • فیلدهای کلیدی: StoryPoint, BusinessValue, Priority, Status

Task

زیرمجموعه مستقیم UserStory (فیلد UserStoryId). هیچ ارتباط مستقیمی با Sprint ندارد.

  • فیلدهای کلیدی: Estimate (ساعت), StartDate, DueDate, Status, Type, Priority

SubTask

زیرمجموعه Task (فیلد TaskItemId). فقط Title و IsCompleted دارد.

OffroadTask

مستقیماً به Project وصل است. برای کارهای خارج از دامنه رسمی پروژه.

۲.۳ فرآیند کاری

  1. ایجاد User Story در Backlog (SprintId = null)
  2. انتقال User Story به Sprint (اسپرینت پلنینگ)
  3. ایجاد Task زیر User Story
  4. ایجاد SubTask زیر Task (اختیاری)

۲.۴ مثال عملی

Backlog: Product Backlog
 └── User Story: "ورود کاربر به سامانه"
      ├── Sprint: "اسپرینت ۱"
      ├── StoryPoint: 5
      └── Task‌ها:
           ├── Task: "طراحی فرم ورود"
           │    ├── SubTask: "ایجاد input ایمیل"
           │    ├── SubTask: "ایجاد input رمز عبور"
           │    └── SubTask: "دکمه ورود"
           ├── Task: "اعتبارسنجی سمت سرور"
           ├── Task: "اتصال به دیتابیس"
           └── Task: "تست ورود"

۲.۵ پاسخ به سوال رایج

نوع کارکجا تعریف کنید
کار رسمی پروژهUser Story → Backlog → Sprint
زیرکار یک User StoryTask (زیر User Story)
جزئیات یک TaskSubTask (زیر Task)
کار ضروری خارج از پروژهOffroadTask (مستقل)

۷. سرویس SignalR — ارتباط بلادرنگ

۷.۱ SignalR چیست؟

کتابخانه مایکروسافت برای ارتباط بلادرنگ (Real-Time) بین سرور و کلاینت. پروتکل‌ها: WebSocket (ترجیحی)، Server-Sent Events، Long Polling.

۷.۲ چرا SignalR؟

  • اعلان جدید رسید → بدون رفرش صفحه نمایش داده شود
  • پیام چت جدید → بلادرنگ دریافت شود
  • کسی آنلاین/آفلاین شد → همه بفهمند
  • کسی تایپ می‌کند → نشان داده شود

۸.۴ پیاده‌سازی

public async Task SendEmailAsync(string to, string subject, string body)
{
    using var client = new SmtpClient(_settings.Host, _settings.Port);
    client.EnableSsl = _settings.EnableSsl;
    client.Credentials = new NetworkCredential(_settings.Email, _settings.Password);
    var message = new MailMessage
    {
        From = new MailAddress(_settings.Email),
        Subject = subject,
        Body = body,
        IsBodyHtml = true
    };
    message.To.Add(to);
    await client.SendMailAsync(message);
}
